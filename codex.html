Điều kiện trước

  • Giải nén toàn bộ MCP ZIP vào đường dẫn ổn định; giữ nguyên mcp/ và service/. Không cần CLI/Owner UI, SDK, repo hoặc .NET runtime. Cần Microsoft Visual C++ v14 x64 Redistributable 14.43.34808 trở lên do owner tự cài; MCP từ chối khởi động trước khi tạo data root nếu thiếu hoặc quá cũ.
  • Chọn đúng data root hiện dùng bởi owner; instance mới sẽ khởi động khóa. Owner phải tự start/provision/unlock qua CLI hoặc Owner UI. Codex/MCP không có quyền unlock, publish catalog, approve/reject, cấp quyền hoặc revoke.
  • Owner cần công bố catalog và phê duyệt request riêng trước khi agent đọc nội dung. Việc kết nối không cấp quyền.

Cấu hình tạm theo process

Thay <isolated-workspace> bằng workspace dự án và <owner> bằng tài khoản Windows; giữ nguyên dấu ngoặc kép và escape kép trong giá trị TOML. Ví dụ cung cấp đúng một instance selector --data-root:

codex -C "<isolated-workspace>" -c 'mcp_servers.metabrain.command="C:\\Users\\<owner>\\AppData\\Local\\MetaBrain\\MCP\\2.0.0\\mcp\\MetaBrain.Mcp.exe"' -c 'mcp_servers.metabrain.args=["--data-root","C:\\Users\\<owner>\\AppData\\Local\\MetaBrain\\Data"]'

This is a process-only -c override; it does not save to the profile or send a prompt. If using an existing settings file, replace the argument pair with ["--config","C:\\...\\service-settings.json"]; do not add both selectors. The path is absolute to mcp/MetaBrain.Mcp.exe; the package selects the adjacent service executable. The arguments are regular paths; Codex string values require doubled backslash escaping as shown.

Kết quả và xử lý

Codex khởi chạy MCP stdio; MCP nối cùng shared host và giữ stdout cho JSON-RPC. Khởi động instance sạch tạo settings không nhạy cảm nhưng vault locked. Owner unlock/approve riêng; agent thấy catalog metadata, request ID/status, và chỉ dữ liệu trong scope sau owner approval + one-time handoff redeem.

Launch failure: xác minh ZIP đã giải nén đầy đủ, executable path absolute tồn tại, đúng một selector và root đúng. Vault locked: owner unlock qua frontend; agent không thể sửa. Request pending/denied: owner review attached-console preview, thu hẹp scope hoặc reject. Thu hồi/lock/restart làm phiên mất hiệu lực. Không cấu hình key/bearer; chỉ đường dẫn handoff/session DPAPI-protected đi qua tích hợp. Đã gửi nội dung cho model/provider thì lock/revoke không thể thu hồi nội dung đó.

Không tự sửa profile toàn cục; xóa/điều chỉnh override tạm trong lệnh khi xong. Hướng dẫn owner duyệt đầy đủ: Tình huống agent truy cập. Chi tiết: Runbook §3.2.1.

Sprint 17: workspace tools

metabrain_workspace_folder_request accepts only a stable folder ID and purpose; the server fixes the requested operation to workspace.file.read and returns an opaque pending receipt. Check only its state with metabrain_workspace_request_status. A folder ID is not inferred from a path, working directory or MCP root.

The owner reviews owner workspace-requests and may record review with owner workspace-request-resolve; resolving is non-authoritative. To grant file reads, the owner separately previews and explicitly approves the exact D108 snapshot with workspace-share-preview and workspace-share-approve. Contextual reads through metabrain_workspace_agent_recall require a separate D111 workspace.agent.recall preview and approval selecting cognitive, hybrid and/or relation operations with exact pins. Semantic hybrid queries still require separate local-inference consent.

Existing metabrain_workspace_context_pack (D110), metabrain_scoped_read, metabrain_source_read and metabrain_propose continue to use their own grants. Workspace recall does not imply source access, proposal authority, provider egress or owner actions. Revoke the relevant grant or lock the vault to deny further calls; content already delivered to a client cannot be recalled.
