Hướng dẫn theo tình huống

Windows x64; các ví dụ dùng gói Meta Brain 1.1.0 và dữ liệu giả định. Thay <install-root>, <data-root>, <control-pipe> bằng giá trị của chính bạn. Đặt install root và data root thành hai thư mục sibling không chồng lấp, ví dụ %LOCALAPPDATA%\MetaBrain\App và %LOCALAPPDATA%\MetaBrain\Data. Không dùng PowerShell bootstrap, tự viết JSON nội bộ hay gửi khóa/bearer vào lệnh.

CLI là đường terminal đầy đủ; Owner UI là đường đồ họa đầy đủ. Cùng một data root và host dùng chung. Cài đặt/mở UI không tự start, provision hoặc unlock. Host khởi động luôn khóa. Chỉ owner mới provision/unlock, quyết định chia sẻ, phê duyệt, thu hồi và phục hồi; agent chỉ khám phá catalog đã công bố, gửi request và đọc đúng phạm vi đã cấp.

  2. Ghi research/note

1. Bắt đầu lần đầu

Prerequisites: Windows x64 phù hợp giới hạn phát hành; bộ cài 1.1.0, không cần SDK/.NET/PowerShell. Bộ cài unsigned; xác minh SHA-256 từ nguồn tin cậy, không tắt SmartScreen/Defender. Dùng sibling roots.

CLI

  1. Mở bộ cài CLI bằng GUI, hoàn tất cài đặt. Không cần quyền admin hay sửa PATH.
  2. Trong terminal dùng executable đầy đủ: 
    "<install-root>\cli\MetaBrain.Cli.exe" --version
"<install-root>\cli\MetaBrain.Cli.exe" --help
"<install-root>\cli\MetaBrain.Cli.exe" lifecycle start --data-root "<data-root>"
"<install-root>\cli\MetaBrain.Cli.exe" lifecycle status --data-root "<data-root>"
"<install-root>\cli\MetaBrain.Cli.exe" owner provision --control-pipe "<control-pipe-from-status>"
"<install-root>\cli\MetaBrain.Cli.exe" owner unlock --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner status --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner lock --control-pipe "<control-pipe>"

Provision displays a recovery key once: store it offline in a place you control; never paste it into a website, model, config, log or evidence. Passphrase/recovery credential is entered only at secure prompt. Wrong credentials are refused; re-check the selected root and use the original credential, or the saved recovery key. Lost both means no fabricated recovery.

Owner UI

  1. Double-click the dedicated Owner UI setup EXE. In graphical setup choose install location and data location; if a component already exists, use its recorded data root.
  2. Launch Owner UI. In Owner session choose Choose folder…, select/create the sibling data root, then Use this folder; select Start service. Use Connect to service if already running. Check status reports the actual host.
  3. In Vault & key, provision with passphrase, safely store once-shown recovery key, then unlock. Lock with Lock vault now. Never type recovery material into ordinary text fields.

Expected: one shared host, status locked before unlock; lock clears private views. Start is not unlock. If root is overlapping/incorrect, select sibling root; if host unavailable check status and connect/start explicitly. Closing the window does not stop another frontend's host.

2. Ghi research/note và đọc lại

Prerequisites: selected running instance, unlocked owner vault, intended zone. Capture persists your source before any optional model work; it does not fetch a URL or call a provider.

CLI

"<install-root>\cli\MetaBrain.Cli.exe" owner research-capture --control-pipe "<control-pipe>" --resource-id synthetic-capture-01 --zone-id research --title "Cache investigation" --text "Synthetic observation: cache miss follows stale key"
"<install-root>\cli\MetaBrain.Cli.exe" owner research-read --control-pipe "<control-pipe>" --resource-id synthetic-capture-01

Use owner research-capture --help and owner research-read --help for required inputs; use the returned ID and revision for exact read-back. No hand-written JSON.

Owner UI

Open Inbox; enter a synthetic note, choose zone and optional metadata, select Save capture, then Use saved capture and Read it back. Compare exact text and source attribution.

Refusal while locked: unlock first. A failed save means no source is assumed saved; retry only after reading the displayed outcome. Keep private source text out of screenshots and shared artifacts.

3. Tìm lỗi hoặc quyết định cũ

Prerequisites: unlocked owner vault and library index. Search results are evidence-bearing references, not proof by ranking alone.

CLI

"<install-root>\cli\MetaBrain.Cli.exe" owner library --control-pipe "<control-pipe>" --query "cache miss" --current current
"<install-root>\cli\MetaBrain.Cli.exe" owner index-status --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner index-rebuild --control-pipe "<control-pipe>"

Use owner library --help for zone, collection, kind, level, current/history/all, time and paging filters. Open a hit's detail/evidence and inspect citations, source availability, revision and current/history state before relying on it. If index-status says stale, explicitly run index-rebuild, then repeat search; do not treat stale results as current.

Owner UI

Open Library, enter query, set available zone/collection/kind/level/currentness/time filters, then open a result and inspect Evidence and History. Use Rebuild library index only when the view reports stale index; refresh and re-run query. Missing source remains a disclosed missing citation, not silently repaired.

4. Dùng lại session coding

Prerequisites: owner vault unlocked; selected running instance; a Codex or OMP session file already written by that client inside an isolated workspace; an owner-chosen zone. Only the sources you enroll are read — one exact file, or the members of one folder you select and confirm: the service never scans a profile, lists a home directory, copies originals or migrates them. Originals stay where the client wrote them and are not re-encrypted by Meta Brain; imported records, checkpoints, mappings and snapshots are encrypted in the vault.

CLI

The shipped normalizers accept codex.session.jsonl version 1 and omp.session.jsonl version 1; any other format/version is refused explicitly. The enrollment request file is the documented CLI input for the private locator, so the path never appears in arguments or replies:

{"locator": "C:\\Users\\<owner>\\sessions\\codex-2026-10-26.jsonl"}

Enroll that one file, inspect the allowlist and status, then ingest from the persisted checkpoint:

"<install-root>\cli\MetaBrain.Cli.exe" owner source-enroll --control-pipe "<control-pipe>" --source-id "<source-id>" --zone-id "<zone-id>" --format codex.session.jsonl --format-version 1 --input-file "<enroll-request.json>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-list --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-status --control-pipe "<control-pipe>" --source-id "<source-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-ingest --control-pipe "<control-pipe>" --source-id "<source-id>"

Expected result: the allowlist/status names zone, format/version, generation, life, availability, persisted checkpoint, refresh consent and cache scope without echoing the locator. Ingest reports ingest_advanced, ingest_idle or ingest_partial_pending with event/diagnostic counts; rerunning it continues from the checkpoint and does not duplicate accepted events. Originals are unchanged.

Refresh is per-source opt-in and runs only while unlocked; pause stops status reads, ingest and refresh, resume continues from the persisted checkpoint, and opt-out withdraws consent:

"<install-root>\cli\MetaBrain.Cli.exe" owner source-refresh-optin --control-pipe "<control-pipe>" --source-id "<source-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-refresh --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-pause --control-pipe "<control-pipe>" --source-id "<source-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-resume --control-pipe "<control-pipe>" --source-id "<source-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-refresh-optout --control-pipe "<control-pipe>" --source-id "<source-id>"

The refresh pass reports a result for each source and names every skip as skipped_not_opted_in, skipped_paused, skipped_revoked or skipped_quarantined.

An unresolved zone/format mapping is held, never guessed. Submit the exact locator with only the fields you know, then withdraw the held row if you cannot resolve it (withdraw enrolls nothing):

"<install-root>\cli\MetaBrain.Cli.exe" owner source-mapping-submit --control-pipe "<control-pipe>" --source-id "<source-id>" --input-file "<enroll-request.json>" [--zone-id "<zone-id>"] [--format codex.session.jsonl --format-version 1]
"<install-root>\cli\MetaBrain.Cli.exe" owner source-mapping-resolve --control-pipe "<control-pipe>" --source-id "<source-id>"

A missing file is reported as source_missing or source_unreadable; do not search the profile for it. source-relocate adopts only a candidate whose length and digest match the enrolled --source-generation; a replaced or truncated source is quarantined with its checkpoint frozen and needs explicit re-enrollment before new bytes are adopted. source-revoke removes the enrollment. Give relocation the same one-key locator request file:

"<install-root>\cli\MetaBrain.Cli.exe" owner source-relocate --control-pipe "<control-pipe>" --source-id "<source-id>" --source-generation <generation-from-status> --input-file "<replacement-request.json>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-revoke --control-pipe "<control-pipe>" --source-id "<source-id>"

Preservation is a separate explicit opt-in; nothing is snapshotted by default. Register the metadata-only preservation reference first and read back its revision; preserve then verifies that reference's zone and locator against the live enrollment before freezing bytes:

{"title": "Codex session reference", "locator": "C:\\Users\\<owner>\\sessions\\codex-2026-10-26.jsonl", "version": "reference-v1", "availability": "available", "creationMethod": "directWrite"}
"<install-root>\cli\MetaBrain.Cli.exe" owner source-create --control-pipe "<control-pipe>" --resource-id "<source-id>" --zone-id "<zone-id>" --input-file "<reference-request.json>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-read --control-pipe "<control-pipe>" --resource-id "<source-id>"

Then preserve one generation with an explicit future UTC retention, list it, and export only to a new file you choose:

"<install-root>\cli\MetaBrain.Cli.exe" owner source-snapshot-preserve --control-pipe "<control-pipe>" --source-id "<source-id>" --source-revision <reference-revision> --retain-until-utc "<future-UTC-instant-Z>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-snapshot-list --control-pipe "<control-pipe>" --source-id "<source-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-snapshot-read --control-pipe "<control-pipe>" --snapshot-id "<snapshot-id>" --snapshot-revision <listed-revision> --output-file "<new-file>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-snapshot-retain --control-pipe "<control-pipe>" --snapshot-id "<snapshot-id>" --expected-revision <live-revision> --retain-until-utc "<future-UTC-instant-Z>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-snapshot-purge --control-pipe "<control-pipe>" --snapshot-id "<snapshot-id>" --expected-revision <live-revision>"

Expected result: preservation reports the snapshot ID, revision, source generation and retention; read exports the exact bytes only when you name a new output file (no stdout body or temporary plaintext file), and retain/purge act on the live revision. Retention must be an explicit future UTC instant (Z or +00:00); after it lapses the bytes authorize nothing.

Refusals and remediation: an unregistered format/version is ingest_unsupported_format (use one of the two shipped formats); without raw-preservation consent an unsupported record makes the checkpoint stop at its byte offset (ingest_partial_pending) and nothing becomes an event; with consent the exact bytes are preserved in the same checkpoint write and may then be passed; missing/changed/unreadable originals require relocation by exact generation or explicit re-enrollment, never a scan; a changed, replaced or truncated source is quarantined with a frozen checkpoint; preservation refuses source_not_enrolled, source_reference_mismatch, source_paused, source_quarantined, source_revoked, source_missing or source_changed with that exact reason; a locked vault stops private reads, ingest, refresh and preservation until you unlock deliberately; a stale snapshot revision refuses, so reopen the live record before retain/purge.

Owner UI

Open Sources and select Read sources (listing opens no transcript). Under Enroll a source (explicit mapping — nothing enrolls by itself), fill Source ID (you name it), Zone, Format, Format version and File on this machine (or Choose file…), then select Enroll this source. The allowlist row is the service's own mapping, life, checkpoint, quarantine, availability and cache-scope answer.

With the row selected, Ingest selected source advances the checkpoint; Pause selected source, Resume selected source, Opt selected into refresh, Opt selected out of refresh and Run refresh pass are the same explicit controls. Refresh pass (only opted-in sources are read) lists each result or skip reason. For an unresolved mapping, fill Source ID (you name it), Locator file and only the Zone (if known)/Format (if known)/Format version you know, then Hold mapping for review; the held row carries the unresolved detail and Withdraw held mapping enrolls nothing. Relocate selected source… accepts only matching bytes; Revoke selected source removes the enrollment.

For preservation, still under Sources: in Preserved snapshots (explicit opt-in — never automatic), enter the enrolled Locator file and select Register selected reference; then Use selected source fills Source ID and Source revision, choose a future Retain until (UTC) and select Preserve this snapshot. List snapshots of selected, Extend selected retention and Purge selected snapshot act on the selected row. Snapshot content is never shown in the view; export only through the CLI output file when you explicitly name one. Keyboard: Enter opens the selected row, F5 re-reads sources and collections, Ctrl+L locks the vault.

Chọn cả thư mục (1.1.0) — CLI

1.1.0 cho phép owner chọn một thư mục thay vì từng file. Chỉ thư mục đã chọn được duyệt; service không quét home/profile. Chọn đường dẫn tuyệt đối, khai báo đệ quy và include/exclude glob; preview có giới hạn và chỉ chứa metadata (đường dẫn tương đối kèm lý do loại), không mở transcript. Gõ đúng ENROLL để xác nhận preview đang hoạt động; mọi giá trị khác hủy và không đổi membership. Include glob bắt buộc; tối đa 16 pattern tương đối, mỗi pattern ≤256 ký tự; không dùng đường dẫn tuyệt đối, cú pháp ổ đĩa, . hay ..; duyệt dừng ở 512 entry. Root bị từ chối nếu bất kỳ thành phần nào từ gốc ổ đĩa tới thư mục chọn là reparse point; entry reparse bên dưới bị loại. Xác nhận chỉ đăng ký metadata mã hóa (không phải body); trùng lặp là idempotent; nếu enrollment bị gián đoạn, unlock dọn record chưa commit, còn nếu báo source_folder_recovery_pending thì sửa lỗi lưu trữ rồi owner lock → owner unlock để recovery chạy lại.

"<install-root>\cli\MetaBrain.Cli.exe" owner source-folder-enroll --control-pipe "<control-pipe>" --folder "<absolute-folder>" --zone-id "<zone-id>" --format codex.session.jsonl --format-version 1 --recursive true --include-globs "**/*.jsonl" --exclude-globs "archive/**"

Refresh thành viên thư mục là opt-in riêng, mặc định tắt, áp dụng cho file thường khớp hiện tại lẫn tương lai trong root/include/exclude đã lưu (không theo reparse). File mới đi qua cùng incremental reader/checkpoint; source-list/source-status báo folderId và folderRefreshOptIn. Opt-out dừng đọc và dừng phát hiện thành viên nhưng không revoke/xóa/purge member; file bị xóa vẫn enrolled và báo missing. Pause/revoke/opt-out từng source vẫn là veto; folder opt-out và vault lock hủy lượt refresh tại read boundary và không nâng checkpoint.

"<install-root>\cli\MetaBrain.Cli.exe" owner source-folder-refresh-optin --control-pipe "<control-pipe>" --folder-id "<folder-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-refresh --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-folder-refresh-optout --control-pipe "<control-pipe>" --folder-id "<folder-id>"

Giữ nguyên byte chưa hiểu được là consent riêng, không bật cùng enrollment hay folder refresh. Opt-in cần deadline UTC tương lai, hoặc truyền --raw-preservation-until-utc ngay khi enroll thư mục; bỏ trống thì member ở trạng thái reference-only. Khi có consent, record chưa hiểu hoặc invalid UTF-8 hoàn chỉnh được lưu byte-for-byte vào encrypted journal cùng checkpoint; barrier phiên bản OMP mới hơn giữ checkpoint tại barrier và giữ nguyên toàn bộ tail. source-preserved-record-read chỉ trả exact span khi vault đang mở và bạn nêu một file output mới.

"<install-root>\cli\MetaBrain.Cli.exe" owner source-raw-preservation-optin --control-pipe "<control-pipe>" --source-id "<source-id>" --retain-until-utc "<future-UTC-instant-Z>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-preserved-record-read --control-pipe "<control-pipe>" --source-id "<source-id>" --offset <byte-offset-from-status> --output-file "<new-file>"
"<install-root>\cli\MetaBrain.Cli.exe" owner source-raw-preservation-optout --control-pipe "<control-pipe>" --source-id "<source-id>"

Trạng thái và retention: status báo bốn facet độc lập — availability, preservation, interpretation, derivation — không gộp thành một nhãn. Sau retainUntilUtc, read của span đó bị từ chối với source_preserved_record_expired; span vẫn nằm trong journal, source-status vẫn liệt kê kèm deadline, bốn facet và journal revision không đổi. Hết hạn không purge hay rewrite gì; xóa span vẫn cần một hành động owner rõ ràng. Opt-out chỉ dừng giữ byte mới, không rút ngắn retention đã lưu và không xóa span.

Sự cố thường gặp: ingest_unsupported_format là sai format/version đã ship; ingest_partial_pending là checkpoint đang dừng ở record chưa hiểu (bật raw preservation nếu bạn muốn giữ và đi tiếp); source_preserved_record_expired là deadline đã qua; skipped_not_opted_in/skipped_paused/skipped_revoked/skipped_quarantined là lý do folder refresh bỏ qua; source_folder_recovery_pending xử lý như trên. Không tự sửa journal hay chép đè originals.

Chọn cả thư mục (1.1.0) — Owner UI

Trong Sources, chọn một folder, nhập zone và format, chọn rõ đệ quy cùng include/exclude glob, rồi yêu cầu preview metadata có giới hạn. Danh sách hiện đường dẫn tương đối và lý do loại mà không mở transcript. Gõ đúng ENROLL để xác nhận preview đang hoạt động; giá trị khác không đổi gì và bạn có thể bỏ preview để chọn folder khác. Ô Explicitly preserve unsupported raw bytes là consent độc lập, mặc định tắt và cần deadline UTC tương lai; enrollment lẫn folder refresh không tự bật nó. Sau khi đọc sources, chọn một member để xem folder ID, trạng thái member và consent refresh do service báo; Opt selected folder into refresh là hành động owner riêng và không vượt qua pause/revoke/opt-out của từng member. View không render transcript hay preserved bytes; export một span chính xác bằng CLI khi bạn nêu file output, và facet nào service không báo thì hiện not reported thay vì 0.

Owner vs agent: only the owner enrolls, maps, ingests, grants refresh consent, preserves/retains/purges and revokes. An agent never enrolls a source, scans a profile, receives a private locator or reads a source/snapshot without an explicit source or snapshot grant; catalog metadata and granted retrieval are its only paths, and lock/revoke/expiry deny the next call.

Privacy: originals stay read-only in place and are not re-encrypted by Meta Brain; the request files above carry the locator instead of arguments or replies, and the UI never echoes it after sending. Imported copies, checkpoints, mappings, collections and snapshots remain encrypted; locking clears the view and stops private reads. Never place vault content, keys, tokens or recovery material in a command line, screenshot or shared artifact. Functional evidence for these existing source and Sources-console workflows is inherited from accepted Sprint 9 (and earlier Sprint 3/5/8) acceptance; this guide makes no fresh client/product-run claim.

5. Cho agent truy cập đúng phạm vi

Prerequisites: owner vault unlocked, agent MCP connection registered, owner has decided what may be published. Catalog publication exposes metadata only. A request is not permission; the agent cannot unlock, publish, approve, issue/revoke grants or see private bodies before approval.

CLI owner path

"<install-root>\cli\MetaBrain.Cli.exe" owner catalog-list --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner catalog-preview --control-pipe "<control-pipe>" --catalog-id "<catalog-id>" --label "Synthetic project memory" --description "Public summary only" --resource-id "<item-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner catalog-publish --control-pipe "<control-pipe>" --catalog-id "<catalog-id>" --label "Synthetic project memory" --description "Public summary only" --resource-id "<item-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner requests --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner request-preview --control-pipe "<control-pipe>" --request-id "<request-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner request-approve --control-pipe "<control-pipe>" --request-id "<request-id>" --preview-id "<preview-id>" --operations memory.read,memory.search --resource-ids "<approved-id>" --expires-at-utc "<future-UTC-instant-Z-or-+00:00>" --handoff-file "<new-private-file>"

Preview each exact publication before typed PUBLISH; publish only chosen metadata. Request preview must run attached: redirected output refuses (preview_redirect_denied). Match --operations to the previewed request, narrow resources if appropriate, and set an explicit future UTC expiry. Typed APPROVE confirmation is required. Handoff is DPAPI-protected; pass its path only to intended agent. Never expose raw token. Use owner catalog-withdraw and owner session revoke operations to withdraw or revoke as needed.

Owner UI path

In Sharing, publish only selected catalog entries; review each request, exact preview and proposed operations/resources. Narrow scope, select a future expiry, approve explicitly, and provide the protected handoff file path to the intended agent. Reject requests you do not understand. In Sessions, inspect and revoke active access when no longer needed.

Agent side: list/query published catalog, submit request with purpose and context, check status, redeem owner-provided handoff once, then use only granted operations/resources. Lock, restart and revoke invalidate access; agent must not attempt owner actions. Prior content already sent to an AI provider cannot be recalled.

Separate connection setup: Codex guide · OMP guide.

6. Đề xuất và quan hệ

Prerequisites: agent has explicit proposal/relation scopes and readable endpoint resources; owner vault unlocked for review.

CLI owner path

"<install-root>\cli\MetaBrain.Cli.exe" owner proposal-list --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" owner proposal-read --control-pipe "<control-pipe>" --resource-id "<proposal-id>"
"<install-root>\cli\MetaBrain.Cli.exe" owner proposal-publish --control-pipe "<control-pipe>" --resource-id "<proposal-id>" --resource-revision <reviewed-revision> --body "<reviewed-body>"
"<install-root>\cli\MetaBrain.Cli.exe" owner proposal-reject --control-pipe "<control-pipe>" --resource-id "<proposal-id>" --resource-revision <reviewed-revision> --reason "Synthetic rejection reason"
"<install-root>\cli\MetaBrain.Cli.exe" owner relation-list --control-pipe "<control-pipe>"

Use owner proposal-publish --help for all friendly attribution fields; review attribution, citations, revisions and currentness before publishing. A stale revision refuses. Review and explicit publish/reject are CLI-supported; for undo of a published proposal use the Owner UI Review Queue undo action (do not infer an inverse CLI operation). For relations use owner relation-create --help, then inspect pinned endpoints and typed relation before relation-accept, relation-reject, relation-unlink or relation-relink; a similarity is not support.

Owner UI path

Open Inbox / review queue, select proposal, inspect source and attribution; explicitly publish or reject, and use the available undo action when needed. In Relations, choose both pinned endpoints and a typed relationship; review before accept/reject/unlink/relink.

An agent proposal remains pending until owner action. Refused stale revisions require re-reading current evidence, not approving old draft. Keep proposed text distinct from owner-authored belief.

7. Kết thúc và bảo toàn dữ liệu

Prerequisites: owner has selected the correct instance; for backup, unlocked vault and destination with adequate space; for restore, a trusted encrypted backup, new destination and correct owner credential.

CLI

"<install-root>\cli\MetaBrain.Cli.exe" owner lock --control-pipe "<control-pipe>"
"<install-root>\cli\MetaBrain.Cli.exe" lifecycle restart --data-root "<data-root>"
"<install-root>\cli\MetaBrain.Cli.exe" lifecycle status --data-root "<data-root>"
"<install-root>\cli\MetaBrain.Cli.exe" owner backup --help
"<install-root>\cli\MetaBrain.Cli.exe" owner restore --help
"<install-root>\cli\MetaBrain.Cli.exe" owner --help

Use the exact backup/restore arguments from verb help; backup is encrypted. Restore into a new folder and authenticate using passphrase or recovery key through secure prompts, never command arguments. Upgrade from a complete matching candidate only after host drains/stops; installer refuses live/conflicting runtime rather than claiming success. Khi nâng cấp 1.0.0 → 1.1.0, tạo encrypted backup trước rồi chạy installer trên cùng data root: vault, khóa, endpoint và backup không bị ghi đè, và mở lại bằng khóa của bạn. Một source đã preserve dùng journal v2; binary 1.0.0 cũ fail closed thay vì đọc/ghi đè, và 1.1.0 không tự downgrade journal. Deadline retention của preserved span là hạn đọc, không phải lịch purge (xem mục 4). Uninstall removes application, not data.

Owner UI

In Vault & key, lock; in Owner session explicitly choose Restart service (restart returns locked) or Stop service. Backup & export: choose destination and create encrypted backup while unlocked. Restore: choose backup, new folder and passphrase/recovery credential in protected control, including when vault locked. For upgrade use graphical installer and recorded matching data root; for removal use installer GUI. Verify data root remains selected and intact; reinstall requires owner key and restarts locked.
